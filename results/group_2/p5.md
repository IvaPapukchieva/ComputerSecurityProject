- **Environment Tested**: Python 3.14 on Windows 11 with `asyncssh` and `pytest`.
- **Predefined Users Tested**:
  - `alice` (Role: `professor`, Clearance: `confidential`)
  - `bob` (Role: `student`, `TA`, Clearance: `internal`, Password: `bob-TA-2026!`)
  - `eve` (Role: `student`, Clearance: `public`)
- **Flag Path**: `/projects/confidential/flag.txt`
- **Intended Protections**:
  - **MAC (Bell-LaPadula)**: User clearance must be $\ge$ path sensitivity for read operations ("no read up"). Bob has clearance `internal` (Level 1), whereas `/projects/confidential` requires `confidential` (Level 2).
  - **DAC**: Path `/projects/confidential` has mode `rwxr-x---` owned by `alice:faculty`. Bob is not a member of `faculty` and is treated as `other` lacking the read (`r`) bit.
  - **RBAC**: Longest-prefix match requires `read` permission on `/projects/confidential`.

## 2. Vulnerabilities Identified

### Vulnerability 2.1: Authorization Bypass via Coarse-Grained Cache Keying in Policy Engine

* **(1) Affected submission(s)**: Group 2 (`DreamTeam2`)
* **(2) Vulnerability description**: 
  In `server/policy.py`, `PolicyEngine` implements an in-memory decision cache `self._allow_cache` intended to avoid redundant authorization calculations. However, the cache key generation method truncates the canonical path to only its first path component:
  ```python
  def _cache_key(self, user: str, op: str, full_path: str) -> tuple:
      top = full_path.strip("/").split("/", 1)[0]
      return (user, op, top)
  ```
  Because `_cache_key` maps any path under `/projects/...` (e.g., `/projects/trigger.txt` and `/projects/confidential/flag.txt`) to the identical cache key `(user, op, "projects")`, granting read permission to any benign file under `/projects/` permanently caches an `ALLOW` decision for that user and operation. Subsequent read requests to any confidential or restricted subpath under `/projects/` hit the cache and are immediately granted without executing DAC, MAC, or RBAC checks.
* **(3) Reproduction steps**:
  1. Authenticate to the SFTP server via SSH using Bob's credentials (`bob` / `bob-TA-2026!`).
  2. Attempt a direct read of the flag:
     ```text
     sftp> get /projects/confidential/flag.txt ./flag.txt
     server> STATUS: Permission denied (code 3)
     ```
     *(Direct access is blocked as expected by DAC & MAC).*
  3. Upload and read any permissible file under `/projects/` (or read an existing permitted project file):
     ```text
     sftp> put ./trigger.txt /projects/trigger.txt
     sftp> get /projects/trigger.txt ./trigger_out.txt
     server> STATUS: OK (code 0)
     ```
     *(This caches the tuple `('bob', 'read', 'projects')` in the server's `_allow_cache`).*
  4. Immediately re-attempt downloading the confidential flag:
     ```text
     sftp> get /projects/confidential/flag.txt ./flag.txt
     server> STATUS: OK (code 0)
     ```
     *(Access is granted via cached decision; flag content is retrieved).*
* **(4) Exploitability**: High. Requires authentication as any user who holds legitimate read rights to at least one file or folder under the shared top-level prefix `/projects/` (e.g. `bob` who is a TA).
* **(5) Impact / implications**: High. Complete compromise of the confidentiality of protected files under the affected directory hierarchy. Directly violates the Bell-LaPadula "no read up" requirement and circumvents Discretionary Access Control file modes.
* **(6) Evidence**:
  - Automated reproduction suite: `tests/p5/test_dreamteam2_security.py`
  - Extracted audit log lines from `server/audit.jsonl` (saved in `evidence/p5_audit_extract.jsonl`):
    ```json
    {"timestamp": "2026-11-24T09:07:32.524436+00:00", "user": "bob", "op": "read", "path": "/projects/trigger.txt", "allowed": true, "reason": "Allowed by DAC, MAC, and RBAC"}
    {"timestamp": "2026-11-24T09:07:32.535994+00:00", "user": "bob", "op": "read", "path": "/projects/confidential/flag.txt", "allowed": true, "reason": "Allowed (cached decision)"}
    ```
  - Captured flag plaintext: `FLAG{groupXX_sftp_wins}`
* **(7) Suggested fix**:
  Modify `_cache_key` in `server/policy.py` to key the cache on the exact canonicalized resource path:
  ```python
  def _cache_key(self, user: str, op: str, full_path: str) -> tuple:
      return (user, op, full_path)
  ```
  Alternatively, remove decision caching entirely since in-memory DAC/MAC/RBAC evaluations have negligible overhead.
