# Security Evaluation Report: Group 5

- **Target**: Group 5 (`DreamTeam5`)
- **Evaluator**: Person 5 (p5)
- **Flag Status**: **CAPTURED** (`hey there im the flag! you found me`)
- **Vulnerability Category**: Broken Authentication (Trivial Default Credentials on Superuser / Administrator Account)
- **Overall Resistance Assessment**: **High (Access Control) / Low (Authentication)**

## 1. Overview & Setup

- **Target System**: Hardened SFTP v3 server implementation by Group 5 over `asyncssh` with custom authentication (`auth.py`) and access control policy (`policy.py`).
- **Environment Tested**: Python 3.14 on Windows 11 with `asyncssh` and `pytest`.
- **Predefined Users Tested**:
  - `alice` (Role: `admin`, Clearance: `confidential`, Owner of `/admin`)
  - `bob` (Role: `analyst`, Clearance: `internal`, Owner of `/projects`)
  - `eve` (Role: `intern`, Clearance: `public`, Owner of `/public`)
- **Flag Location**: `/admin/flag.txt`
- **Flag Content**: `hey there im the flag! you found me` *(Note: Group 5 did not use the standard `FLAG{...}` wrapper format)*.
- **Access Control Baseline**:
  - Group 5 implemented a strict conjunctive policy engine requiring $\text{DAC} \land \text{MAC} \land \text{RBAC}$.
  - The access control model resisted unauthenticated and unauthorized requests:
    - `bob` (analyst / internal) requesting `/admin/flag.txt` is stopped at the DAC ancestor check (`/admin` mode `0700` owned by `alice:admins`), MAC (no read up: internal < confidential), and RBAC (no read grant on `/admin`).
    - Directory traversal escapes (`../outside.txt`, `C:/...`, null bytes) are stopped by `safe_join()`.
    - Handles are maintained in a per-session table and rechecked against the authorization gate on `READ`, `WRITE`, and `FSTAT`.

## 2. Vulnerabilities Identified

### Vulnerability 5.1: Trivial Default Credentials on Administrator / Superuser Account (`alice:alice`)

* **(1) Affected submission(s)**: Group 5 (`DreamTeam5`)
* **(2) Vulnerability description**:
  While Group 5 securely stores passwords as salted scrypt hashes (`n=16384, r=8, p=1, dklen=32`) in `data/users.json`, they provisioned trivial, predictable default passwords for their accounts:
  - The administrator account `alice` (holding the `admin` role, `confidential` MAC clearance, and DAC ownership of `/admin`) was set to the trivial password `"alice"` (`username == password`).
  - The analyst account `bob` was similarly assigned `"bob"`.
  Because `data/users.json` is a static dataset provided with the deployment, an attacker auditing or dictionary-checking common passwords against the salted hashes can crack the superuser credentials immediately. With `alice:alice`, the attacker bypasses all access control layers legitimately as the highest-privilege identity.
* **(3) Reproduction steps**:
  1. Audit the user record for `alice` in `data/users.json`:
     ```json
     {
       "username": "alice",
       "salt": "s7VHx8vtjMdM78xkoxYTSA==",
       "password_hash": "ZojH+5EY2HXGXUlwJ9uVsb1SnUK3Bk/J/m3cA3ixBVU="
     }
     ```
  2. Compute `hashlib.scrypt(b"alice", salt=base64.b64decode(salt), n=16384, r=8, p=1, dklen=32)`.
  3. Notice the derived hash matches `ZojH+5EY2HXGXUlwJ9uVsb1SnUK3Bk/J/m3cA3ixBVU=` exactly.
  4. Connect to the running SFTP server via SSH/SFTP as user `alice` with password `alice`:
     ```text
     sftp> get /admin/flag.txt ./flag.txt
     server> STATUS: OK (code 0)
     ```
  5. The server grants access and streams the flag payload.
* **(4) Exploitability**: High. Requires only offline dictionary evaluation against the static user dataset or simple credential guessing against the server.
* **(5) Impact / implications**: High. Complete compromise of the administrative tier. Allows full read/write access across all directories in the jail root, including `/admin` and `/admin/flag.txt`.
* **(6) Evidence**:
  - Automated test in `tests/p5/test_dreamteam5_security.py`: `test_auth_weak_credential_compromise` and `test_live_sftp_flag_retrieval`.
  - Server audit trail (`server/audit.jsonl`):
    ```json
    {"timestamp": "2026-11-24T09:21:47.696385+00:00", "user": "bob", "op": "read", "path": "/admin/flag.txt", "allowed": false, "reason": "dac_denied"}
    {"timestamp": "2026-11-24T09:21:47.781958+00:00", "user": "alice", "op": "read", "path": "/admin/flag.txt", "allowed": true, "reason": "allowed"}
    ```
  - Captured flag content: `hey there im the flag! you found me`
* **(7) Suggested fix**:
  Enforce strong password complexity requirements during credential provisioning (e.g. minimum entropy, rejection of `password == username`) and document generated high-entropy passwords in test configurations rather than using default usernames as passwords.

### Finding 5.2: Non-Standard Flag Format
* **Description**:
  The course specification (Phase 1 PDF §5 and Phase 2 PDF §B) requires flags to follow the standard pattern `FLAG{...}` (e.g. `FLAG{groupXX_sftp_wins}`). Group 5 placed a plain text string in `/admin/flag.txt` (`hey there im the flag! you found me`) without the `FLAG{}` wrapper.
