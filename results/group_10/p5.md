## 2. Vulnerabilities Identified

### Vulnerability 10.1: Broken Authentication / Trivial Credential Pattern (`bobbobbobbob`, `eveeveeveeve`)

* **(1) Affected submission(s)**: Group 10 (`DreamTeam10`)
* **(2) Vulnerability description**:
  In `tools/setup_demo.py` and `server/auth.py`, Group 10 enforced a minimum password length of 12 characters. However, user accounts in `data/users.json` were provisioned with trivial passwords formed by simply repeating the username until reaching the 12-character requirement:
  - Account `bob`: password `"bobbobbobbob"` (`"bob" * 4` = 12 characters).
  - Account `eve`: password `"eveeveeveeve"` (`"eve" * 4` = 12 characters).
  Because salted `scrypt` parameters are public in `data/users.json`, an offline pattern evaluation reveals these passwords immediately. With `bob:bobbobbobbob`, an attacker logs in as the owner of `/projects` and reads `/projects/flag.txt` directly without any access control violations.
* **(3) Reproduction steps**:
  1. Inspect `data/users.json` for `bob`:
     ```json
     {
       "username": "bob",
       "salt": "2X2VmRYXaRGyg2ni0k5w6g==",
       "password_hash": "mz21GMjhOy9ujAwPhXlylfXfhixnsqbCB/d3n9Yjedk="
     }
     ```
  2. Compute `hashlib.scrypt(b"bobbobbobbob", salt=base64.b64decode(salt), n=16384, r=8, p=1, dklen=32)`.
  3. The derived hash matches `mz21GMjhOy9ujAwPhXlylfXfhixnsqbCB/d3n9Yjedk=` exactly.
  4. Connect via SFTP as `bob` with password `bobbobbobbob`.
  5. Open and read `/projects/flag.txt`:
     ```text
     sftp> get /projects/flag.txt ./flag.txt
     server> STATUS: OK (code 0)
     ```
  6. The flag `FLAG{gr0üp-10_SFTP_w1nS}` is exfiltrated.
* **(4) Exploitability**: High. Requires only simple pattern dictionary attacks against the supplied user dataset.
* **(5) Impact / implications**: High. Complete compromise of internal user accounts (`bob`, `eve`), permitting full read/write access across `/projects` and `/public`.
* **(6) Evidence**:
  - Automated test in `tests/p5/test_dreamteam10_security.py`: `test_auth_weak_credentials_compromise` and `test_live_sftp_flag_capture`.
  - Captured flag content: `FLAG{gr0üp-10_SFTP_w1nS}`.
* **(7) Suggested fix**:
  Enforce password entropy checks and dictionary rejection during credential setup rather than only enforcing simple length checks (`len >= 12`).

### Vulnerability 10.2: Access Control Bypass via Symlink Aliasing (`validate_components` Omits Symlink Rejection)

* **(1) Affected submission(s)**: Group 10 (`DreamTeam10`)
* **(2) Vulnerability description**:
  Group 10's authorization engine in `server/policy.py` checks DAC, MAC, and RBAC against the *virtual path* requested by the client (`/public/shortcut`).
  In `data/dac_owners.csv` and `data/mac_labels.json`, `/public` is labelled `public` and has DAC mode `644` (readable by everyone, including unprivileged user `eve`).
  To prevent symlink traversal, `Policy.authorize` invokes `validate_components()`. However, `validate_components()` only checks:
  ```python
  if os.path.commonpath([str(root), str(full.resolve())]) != str(root):
      raise PermissionError('path escape')
  ```
  `validate_components` deliberately omits checking `stat.S_ISLNK(st.st_mode)` (as evidenced by line 100: `# <here was some text removed due to the details related to CTF description>`).
  Because `../projects/flag.txt` resolves inside the jail root (`root / "projects" / "flag.txt"`), the jail check passes. The server opens the target file through the symlink and returns internal confidential data to unprivileged user `eve`.
* **(3) Reproduction steps**:
  1. Authenticate to the server as unprivileged guest `eve` (`eveeveeveeve`).
  2. Request to read `/public/shortcut`:
     ```python
     async with sftp.open("/public/shortcut", "rb") as f:
         data = await f.read()
     ```
  3. The policy engine evaluates `/public/shortcut`:
     - DAC: `file_mode: 644` -> `other` has `r--` -> ALLOWED.
     - MAC: `label: public`, `eve: public` -> ALLOWED.
     - RBAC: `guest` role has `read` grant on `/` -> ALLOWED.
  4. `validate_components` verifies that the resolved target (`root/projects/flag.txt`) remains within `root`.
  5. The file handle is returned and streams `FLAG{gr0üp-10_SFTP_w1nS}` to `eve`.
  6. This attack matches Group 10's own execution record in `server/audit.jsonl` (lines 277-280) and `stolenFlag.txt`.
* **(4) Exploitability**: High. Exploitable by the lowest-privilege guest account `eve`.
* **(5) Impact / implications**: High. Total bypass of MAC ("no read up") and DAC ("other denied") boundaries for any internal file aliased via a public symlink.
* **(6) Evidence**:
  - Target repository evidence: `stolenFlag.txt` at the repository root and `server/audit.jsonl` lines 277-280.
  - Automated test in `tests/p5/test_dreamteam10_security.py`: `test_symlink_alias_vulnerability_structure`.
* **(7) Suggested fix**:
  In `validate_components()`, explicitly inspect `st.st_mode` and reject any component where `stat.S_ISLNK(st.st_mode)` is true.
